# Резервное копирование

Резервная копия позволяет восстановить базу после сбоя или неудачного обновления.
Создавайте её перед изменением конфигурации и регулярно во время работы.
Храните копии отдельно от каталога рабочей базы.

## Сохранение базы

1. Попросите пользователей завершить работу и закройте приложение.
2. Откройте нужную базу в Конфигураторе под администратором.
3. Выберите **Администрирование → Выгрузить информационную базу**.
4. Укажите папку и имя файла. Добавьте в имя дату, чтобы различать копии.
5. Дождитесь сообщения об успешной выгрузке и закройте Конфигуратор.

В выбранной папке появится файл с расширением `.dt`. Он содержит конфигурацию и данные базы.
Отдельно сохраните тексты документов, на которые ссылаются редакции.

Файловую базу также можно скопировать целиком после закрытия всех её сеансов.
Копирование открытого файла `1Cv8.1CD` не обеспечивает сохранность данных.

## Восстановление из копии

Сначала проверьте копию в отдельной базе, чтобы не затронуть текущие данные.

1. Создайте новую пустую файловую базу в другой папке и откройте её в Конфигураторе.
2. Выберите **Администрирование → Загрузить информационную базу**.
3. Укажите подготовленный файл `.dt` и дождитесь завершения загрузки.
4. Откройте восстановленную базу в режиме предприятия.
5. Проверьте вход администратора, сотрудников и несколько последних документов.
   Откройте выпуск, сформируйте отчёт и убедитесь, что доступны внешние тексты.

Если данные открываются корректно, копию можно использовать для восстановления работы.
Перед заменой основной базы определите, что делать с изменениями, внесёнными после выгрузки.
Они не содержатся в более ранней копии.

<details>
<summary>Выгрузка и восстановление с помощью команд</summary>

В комплекте приложения есть вспомогательная команда для закрытой базы.
Для её выполнения нужен Node.js 22 или новее. Откройте PowerShell в папке DocRelease.

```powershell
node .\tools\database.mjs backup --user Администратор
```

Замените имя на свою учётную запись администратора. Выгрузка и журнал сохранятся
в новом каталоге `.local/backups/`. По умолчанию используется база `.local/infobase`.

Для восстановления выберите новый путь:

```powershell
node .\tools\database.mjs restore --dump "путь-к-копии.dt" --base "путь-к-новой-базе"
```

В пути новой базы не должно быть пробелов. Команда откажется загружать данные в непустую папку.
После завершения проверьте восстановленную базу описанным выше способом.

</details>
