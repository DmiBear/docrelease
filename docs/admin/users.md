# Пользователи и сотрудники

Учётные записи создаются в Конфигураторе. Для каждого пользователя указываются имя входа,
полное имя и роль. На рисунке 1 показан пример базы с четырьмя пользователями.

[![Рисунок 1 — Четыре пользователя в списке Конфигуратора.](/images/ui-02-users.png)](/images/ui-02-users.png)

*Рисунок 1 — Четыре пользователя в списке Конфигуратора.*

## Создание пользователя

1. Откройте нужную базу в Конфигураторе.
2. Выберите **Администрирование → Пользователи** и нажмите **Добавить**.
   Откроется карточка на вкладке **Основные** (рисунок 2).

[![Рисунок 2 — Вкладка «Основные» новой учётной записи до заполнения.](/images/ui-18-user-basics.png)](/images/ui-18-user-basics.png)

*Рисунок 2 — Вкладка «Основные» новой учётной записи до заполнения.*

3. Заполните **Имя** и **Полное имя**. Имя используется для входа, полное имя отображается в приложении.
4. Для входа через окно 1С оставьте **Аутентификацию 1С:Предприятия**.
5. Перейдите на вкладку **Прочие**. Отметьте флажком нужную роль и нажмите **ОК**.

На рисунке 3 показаны доступные роли. Ни одна ещё не отмечена:
выделенная строка сама по себе не назначает роль.

[![Рисунок 3 — Вкладка «Прочие»: список ролей до установки флажка.](/images/ui-16-role-list.png)](/images/ui-16-role-list.png)

*Рисунок 3 — Вкладка «Прочие»: список ролей до установки флажка.*

| Роль | Для кого предназначена |
|---|---|
| **Автор документации** | Для сотрудников, которые готовят редакции и передают их на проверку |
| **Проверяющий документации** | Для сотрудников, принимающих решения по назначенным передачам |
| **Руководитель выпуска** | Для составления планов и выпуска комплектов |
| **Администратор DocRelease** | Для настройки пользователей и обслуживания базы |

В новой базе сначала создайте администратора, закройте Конфигуратор и проверьте повторный
вход под его именем. После этого добавьте остальных пользователей. Ограничения парольной
защиты учебной версии 1С учитывайте при выборе данных для такой базы.

## Связать с сотрудником

Пользователь базы и сотрудник — разные записи. Даже если сотрудник уже есть в справочнике,
его нужно связать с учётной записью. На рисунке 4 эта связь ещё не задана:
столбцы с именем и идентификатором пользователя базы пусты.

[![Рисунок 4 — Сотрудники до связи с пользователями базы.](/images/ui-20-employees-unlinked.png)](/images/ui-20-employees-unlinked.png)

*Рисунок 4 — Сотрудники до связи с пользователями базы.*

1. Войдите в DocRelease под администратором.
2. Откройте **НСИ → Сотрудники** и выберите сотрудника либо создайте новую карточку.
3. В поле **Имя пользователя базы** укажите имя из списка пользователей Конфигуратора.
4. Сохраните карточку.

Поле **Идентификатор пользователя базы** заполнится автоматически. Вернитесь в список
и проверьте оба столбца. На рисунке 5 автор и проверяющий уже связаны
с соответствующими входами.

[![Рисунок 5 — Имена и идентификаторы пользователей заполнены после установки связи.](/images/ui-03-employees.png)](/images/ui-03-employees.png)

*Рисунок 5 — Имена и идентификаторы пользователей заполнены после установки связи.*

Свяжите с сотрудниками автора и проверяющего. Один вход может быть связан только
с одним сотрудником. Если появляется сообщение о повторной связи, найдите прежнюю карточку;
при проверке учитываются и записи, помеченные на удаление.

Если пользователь был создан заново, повторно проверьте связь. Его внутренний идентификатор
может измениться, даже если имя входа осталось прежним.

## Проверка доступа

Проверьте входы пользователей последовательно. Автор должен иметь возможность создать
свою редакцию и передачу, проверяющий — решение по назначенной ему передаче,
руководитель — план и выпуск готового комплекта.

Просмотр справочников доступен всем ролям. Например, на рисунке 6 список сотрудников
открыт под пользователем «Автор документации»; кнопки **Создать** над списком нет.
Изменять учётные записи и связи может администратор.

*Рисунок 6 — Список сотрудников под автором: просмотр без кнопки «Создать».*
