# План комплекта

В плане руководитель выпуска определяет, какие документы должны войти в релиз.
Для каждого документа указываются редакция, ответственный и срок подготовки.

## Основные сведения о релизе

1. Откройте **Документация → План комплекта** и нажмите **Создать**.
   В новой карточке ещё нет продукта и состава комплекта (рисунок 8).

[![Рисунок 8 — Новый план комплекта до заполнения.](/images/ui-10-plan.png)](/images/ui-10-plan.png)

*Рисунок 8 — Новый план комплекта до заполнения.*

2. Заполните сведения о релизе.

| Поле | Что указать |
|---|---|
| **Дата** | Дату составления плана |
| **Продукт** | Продукт, для которого готовится документация |
| **Номер релиза** | Обозначение выпуска продукта, например `1.2` |
| **Куратор** | Сотрудника, отвечающего за подготовку комплекта |

В примере выбраны продукт DocRelease, релиз 1.2 и куратор «Демонстрационный автор»
(рисунок 9). План пока не записан: ещё нужно заполнить состав.

[![Рисунок 9 — Основные сведения плана заполнены; состав ещё пуст.](/images/ui-21-plan-header.png)](/images/ui-21-plan-header.png)

*Рисунок 9 — Основные сведения плана заполнены; состав ещё пуст.*

## Документы комплекта

1. Нажмите **Добавить** над таблицей.
2. В поле **Документ продукта** выберите документ, который должен войти в релиз.

На рисунке 10 выбран только документ. Редакция, ответственный и срок ещё
не заполнены; красное подчёркивание отмечает обязательные сведения.

[![Рисунок 10 — В план добавлен документ; остальные поля строки ещё не заполнены.](/images/ui-22-plan-document.png)](/images/ui-22-plan-document.png)

*Рисунок 10 — В план добавлен документ; остальные поля строки ещё не заполнены.*

3. Выберите **Редакцию**, назначьте **Ответственного** и **Срок подготовки**.
4. Добавьте остальные обязательные документы.
5. Нажмите **Записать и закрыть**.

Сохранённый план появится в списке с номером, продуктом и обозначением релиза
(рисунок 11).

[![Рисунок 11 — Сохранённый план релиза 1.2 в списке.](/images/ui-11-plans.png)](/images/ui-11-plans.png)

*Рисунок 11 — Сохранённый план релиза 1.2 в списке.*

Включайте каждый документ в план один раз. Он должен относиться к продукту из шапки
плана, а выбранная редакция — к этому документу. Повторяющийся документ или чужую редакцию
приложение не позволит сохранить.

Если текст ещё готовится, редакцию можно выбрать позже. Однако для записи плана
нужны хотя бы одна строка, ответственные и сроки. Для выпуска потребуется согласованная редакция
в каждой строке.

Номер релиза продукта и номера редакций документов могут различаться.
После сохранения выполните [проверку готовности](readiness.md).
