# Функциональные требования

Перечень связывает задачи первой версии с реализованными функциями и итоговой приёмкой.
Это описание текущего учебного проекта; внешнее утверждение технического задания не заявляется.

| ID | Требование | Проверка |
|---|---|---|
| F-01 | Вести продукты, виды и карточки документов с принадлежностью продукту | TC-01 |
| F-02 | Хранить редакцию с номером, автором, ссылкой и идентификатором; исключать дубли | TC-02, TC-03 |
| F-03 | Определять обязательный состав релиза с ответственными и сроками | TC-04 |
| F-04 | Передавать редакцию назначенному проверяющему | TC-05 |
| F-05 | Фиксировать согласование или возврат; требовать замечание при возврате | TC-06, TC-07 |
| F-06 | Согласовывать каждую новую редакцию самостоятельно, сохраняя события прежней | TC-08 |
| F-07 | Защищать проверенный текст и основания зависимых операций | TC-09 |
| F-08 | Выбирать для строки плана редакцию именно её документа и продукта | TC-10 |
| F-09 | Рассчитывать все причины неготовности обязательного состава | TC-11, TC-12 |
| F-10 | Выпускать только готовый комплект и сохранять снимок с решениями | TC-13 |
| F-11 | Перепроводить без дублей и не оставлять частичных изменений при отказе | TC-14 |
| F-12 | Выводить готовность, актуальную очередь и историю редакции | TC-15 |
| F-13 | Разграничивать запись по ролям и реальному назначенному сотруднику | TC-16 |

Проверенная среда — файловая учебная 1С 8.3.27.1508, один последовательный сеанс,
без сервера и COM. Воспроизведение приложения из исходников на чистой базе проверяет TC-17.
Доступность внешнего текста и его содержание проверяются людьми; сетевой контроль ссылки
и автоматическое вычисление хэша средствами 1С не реализованы.

Результаты — [TC-01–TC-17](acceptance.md), правила — [жизненный цикл](../../docs/reference/lifecycle.md).
