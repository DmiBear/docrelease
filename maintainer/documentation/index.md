# Как вести документацию

Источники документации — обычные Markdown-файлы, изображения и конфигурация VitePress.
Собранный HTML не редактируется. Публикуемая копия отделена от основной рабочей базы:
изменения руководств ведутся здесь, новые исходники 1С переносятся осознанным обновлением снимка.

1. Создайте ветку для изменения.
2. Исправьте страницу и связанные справочные сведения; при изменении интерфейса обновите иллюстрацию.
3. Выполните `npm.cmd run check`, просмотрите сайт и поиск.
4. В описании изменения укажите задачу, версию приложения, изменённый сценарий и выполненные проверки.
5. После рецензирования объедините изменения и подготовьте новую редакцию документации.

| Материал | Где хранить |
|---|---|
| Руководство пользователя | `docs/user/` |
| Руководство администратора | `docs/admin/` |
| Установка | `docs/deployment/` |
| Общие определения | `docs/reference/` |
| Иллюстрации интерфейса | `docs/public/images/` + запись в манифесте |
| Исходники схем | `diagrams/`; отображаемая SVG в `docs/public/diagrams/` |
| Локальные базы и журналы | `.local/`, исключено из Git |

Каждая страница содержит `title`, `description`, `doc_id`, `app_version`, `docs_version`, `reviewed`.
Три руководства имеют ID `DR-USER`, `DR-ADMIN`, `DR-INSTALL`; общие материалы — `REF`.
Глобальная версия задаётся в `project.json`. Изменение версии сопровождается проверкой всех страниц.

Используйте [редакционные правила](style.md), [порядок выпуска](release.md) и
[инструкцию публикации](publishing.md). Команды и правила репозитория не создают автоматически
решение «Согласовано» в базе 1С.
